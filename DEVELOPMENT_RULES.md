# Development Rules

## 1. General workflow

Работать небольшими, проверяемыми этапами.

Перед изменениями:
1. Изучить текущий код.
2. Найти связанные тесты.
3. Определить минимальный объём изменений.
4. Учитывать обратную совместимость.

После изменений:
1. Проверить синтаксис.
2. Запустить релевантные тесты.
3. При необходимости запустить полный набор.
4. Просмотреть diff.

Не переписывать большие файлы без необходимости.

## 2. Git rules

- Никогда не выполнять `git add .`.
- Добавлять только явно согласованные файлы.
- Не включать `.env`, секреты, базы данных, backups и временные файлы.
- Не создавать коммиты без явного разрешения пользователя.
- Не выполнять push без отдельного явного разрешения.
- Перед коммитом запускать полный `.\run_tests.ps1`.
- Перед коммитом показывать список подготовленных файлов и diff stat.
- Запрашивать подтверждение пользователя.
- При отказе очищать индекс от выбранных файлов, не удаляя изменения рабочего дерева.
- Не объединять функциональные изменения и инфраструктурные инструменты без необходимости.

## 3. Encoding

Единый стандарт: UTF-8.

- Не допускать mojibake.
- Не менять кодировку файлов без необходимости.
- PowerShell-файлы сохранять в UTF-8 без BOM, если это совместимо с текущей конфигурацией.
- Не удалять существующие резервные копии.
- После изменений русскоязычных строк запускать `test_encoding.py` или полный набор тестов.

## 4. Testing

Быстрые тесты запускать для конкретных изменённых модулей.

Полный regression suite:
`.\run_tests.ps1`

Не считать проверку синтаксиса заменой тестированию.

При ошибке:
- сохранить полный traceback;
- определить первопричину;
- не скрывать ошибку изменением тестов;
- не объявлять задачу завершённой до успешной проверки.

## 5. Database and configuration safety

- Не изменять `.env` и секреты без необходимости.
- Не удалять `ci_test.db`.
- Не удалять или не очищать рабочие базы данных.
- Изменения схемы БД должны быть осознанными и протестированными.
- В тестах использовать изолированную тестовую конфигурацию.

## 6. Commercial data integrity

- Не создавать дубли товаров без проверки.
- Не смешивать внутренний товар каталога с предложением конкретного поставщика.
- Сохранять связь импортированных строк с источником.
- Не считать цену проверенной только потому, что она импортирована.
- Не предполагать фиксированный формат Excel.

## 7. Working style

- Предпочитать минимальные изменения.
- Не выполнять скрытые массовые преобразования.
- Объяснять цель нетривиальных изменений.
- Не удалять неизвестные файлы.
- Не менять архитектуру по собственной инициативе без объяснения причин.
